What LLM4L5X does

Everything runs on this PC. Nothing is imported into Studio 5000 until you import the file yourself, so review every rung first.

1 · Plain English → ladder

Describe the logic the way you would to a colleague: "Start the pump with the start button and keep it running until stop is pressed." A local model reads it; checked code builds the rungs.

You get the rungs, a plain-English read-back of what they do (check this first), the new tags, and the checks.

Export: Routine.L5X (a new routine) or Rung.L5X (rungs to paste), chosen in Settings. Copy gives the rung text in neutral or ASCII form, also chosen in Settings.

2 · Rung text: ASCII ↔ neutral

Paste rungs in either form:

XIC(a)[XIC(b) ,XIO(c) ]OTE(d); neutral text, as stored in L5X
XIC a BST XIC b NXB XIO c BND OTE d ASCII text, as in the editor's ASCII mode

You get the other form, what each rung does in plain English, and the checks. Copy gives the other form; Download gives Routine.L5X or Rung.L5X with the tags it needs.

3 · Attach your project

Attach (or drop a file on the input box) a Studio 5000 export: the whole controller, a program, a routine or rungs. New logic then uses your real tag names, data types and Add-On Instructions, and the Logix Designer version.

explain all rungs: every rung in plain English. validate: see 4. summary: what the file holds. xref TagName: where a tag is used.

4 · Validate

Two layers. Import checks: will Studio 5000 accept it (syntax, operands, data types, tags that exist, instruction names for your version).

Rules: 49 programming rules with fixed codes: CRT critical, ERR error, WAR warning, INF info. Switch rules on or off on the Rules page. Write lint:disable=ERR010 in a rung comment or tag description to accept one case.

Generated and pasted rungs are checked with the rung rules too. Project rules (tasks, modules, descriptions) need a full controller export.

5 · UDTs

Switch the input to UDT and describe the data: "A motor UDT with running and faulted bits, speed in rpm and 32 alarm bits." Or attach an Excel sheet (template under ⓘ). Members are written in the order that wastes no memory; you get Name.L5X (one UDT) or a zip. Import with Data Types → Import Data Type.

Optimize: attach a UDT export, or a whole program and press optimize UDTs. Each UDT shows the bytes saved per instance, how many instances there are, and anything that copies it by byte offset (COP/CPS, MSG, produced/consumed). Download one file, a zip, or the whole program. A UDT can only change offline, and the whole-program file needs a test import first.

6 · The model

Set it up in Settings: Ollama, or a llama.cpp server, which constrains every answer to valid logic. Turn thinking off: it is much faster on a CPU.

Tested: Qwen3.6-35B-A3B on llama.cpp got 99% of the built-in test suite right. Real requests are worded differently, which is why the read-back is there.

Tips

Name tags exactly as they are in the project. Say "latch" when you mean OTL; "turn on" means a normal coil. Say "on-delay" or "off-delay" for timers. Put the condition first when there are several actions: "When A is on, start the conveyor and reset the counter."
