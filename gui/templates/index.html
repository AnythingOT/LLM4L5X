What LLM4L5X does

Runs locally with a local model, completely offline. Nothing reaches Studio 5000 until you import a file yourself: test it before it runs in production.

Plain English to ladder

Input
Start the pump with the start button and keep it running until stop is pressed.
Output
The rungs drawn as ladder, what they do in plain English, and the checks. Routine.L5X or Rung.L5X, as chosen in Settings. Copy gives the rung text in neutral or ASCII form, also chosen in Settings.

Plain English to UDT

Input
Switch the input to UDT: A motor with running and faulted bits, speed in rpm and 32 alarm bits.
Output
Name.L5X for one UDT, a zip for several, members in the order that wastes no memory. In Studio 5000: Data Types, Import Data Type.

Rung text to ladder

Input
Neutral text, as stored in L5X:
XIC(a)[XIC(b) ,XIO(c) ]OTE(d);
ASCII text, as in the editor:
XIC a BST XIC b NXB XIO c BND OTE d
Output
The rungs drawn as ladder, in plain English, with the checks. Routine.L5X or Rung.L5X, as chosen in Settings.

Attach an L5X

Input
A Studio 5000 export: the whole controller, a program, a routine, rungs or a UDT. New logic then uses its tags, AOIs and version.
Output
Explain all rungs: every rung drawn and in plain English. xref TagName: where a tag is used.
Validate: will Studio 5000 import it, and the coding rules, UDT rules included (padding, member order, unused, descriptions). Switch rules on or off on the Rules page.
Optimize UDTs: reorder members to save memory; one file, a zip or the whole program.

Attach a requirements Excel

Input
Each sheet is one routine, each row one requirement in plain English. A row may give rung text instead, which is used as written. Sample in the examples list, next to Send.
Output
Rows are built one by one, drawn as they finish. One Routine.L5X per sheet (a zip with a report when there are several), the requirement as the rung comment.

Attach a UDT Excel

Input
One row per member: UDT, UDT description, Member, Data type, Description. Sample in the examples list in UDT mode.
Output
The UDTs, checked and ordered, as Name.L5X or a zip.

The model

Set it up in Settings: Ollama, or a llama.cpp server, which constrains every answer to valid logic. Turn thinking off: it is much faster on a CPU.

Tested: Qwen3.6-35B-A3B on llama.cpp got 99% of the built-in test suite right. Real requests are worded differently, which is why the read-back is there.

Planned

Documentation written from an attached program: what each routine does, from its rungs.

Translate to English: rung comments, tag descriptions and tag names of a project written in another language.

Tips

Name tags exactly as they are in the project. Say "latch" when you mean OTL; "turn on" means a normal coil. Say "on-delay" or "off-delay" for timers. Put the condition first when there are several actions: "When A is on, start the conveyor and reset the counter."
